# 柏里挑怡 · 独立内容编辑器实施计划

> 配套设计与数据约束见 [content-editor-plan.md](./content-editor-plan.md)。
>
> 本文只描述怎么实施；每次对话结束后，把结果写入 [content-editor-progress.md](./content-editor-progress.md)。

## 0. 固定架构决策

- 编辑器是独立的本机 Next.js 应用，不加入网站前台路由。
- 编辑器直接读取 `CONTENT_REPO_PATH` 指向的网站本地仓库。
- 编辑器写入 `content/` 和 `public/static/same-styles/`，再执行本地 Git commit/push。
- 网站仍由现有 Next.js + Velite 构建，Vercel 继续从 GitHub 部署。
- 首版完整支持同款、行程、动态的新增、编辑、删除、草稿和发布。
- 首版标签支持候选读取、去重、新增和基础列表；不做批量改名或合并。
- 首版不做定时发布、多人权限、回收站、富文本、图库和部署状态。

## 1. 实施前基线

### 工作内容

1. 保存当前网站在桌面端和移动端的截图与构建结果。
2. 记录当前工作区未提交修改，禁止编辑器实施过程覆盖这些修改。
3. 确认目标分支、GitHub 远端和 Vercel 部署分支。
4. 确认独立编辑器项目目录，例如 `D:/projects/cp-site-editor`。

### 产出

- 基线记录写入进度备忘录。
- 编辑器项目目录和网站仓库目录明确分离。

### 验收

- 能在不修改网站代码的情况下运行当前 `npm run build`。
- 已知的未提交修改有清单可追溯。

## 2. 内容契约与兼容测试

### 工作内容

1. 为同款、行程、动态建立 TypeScript 内容契约。
2. 固定成员值 `A | B | both`，后台只显示中文名称。
3. 增加兼容字段：`id`、`status`、`slug`、`updatedAt`、`publishedAt`。
4. 明确动态和行程以 `description` 为前台展示正文；同款保留 MDX body。
5. 明确日期是本地日期，时间戳使用 `Asia/Shanghai` 的 ISO 8601。
6. 用现有 MDX 文件建立读取、写回和边界测试样本。

### 产出

- 字段映射表和枚举定义：`docs/content-editor-contracts.md`。
- 旧文件、缺字段、特殊字符和非法内容样本：`docs/content-editor-fixtures/`。
- 标题修改、重复标题、旧图片路径和空可选字段的测试用例。

### 验收

- 旧内容无需迁移即可被完整读取。
- 写回后未知 frontmatter、标签和正文换行不丢失。
- 标题或日期修改不会让编辑器失去记录。

## 3. 创建独立编辑器应用

### 工作内容

1. 创建独立 Next.js + TypeScript 项目，不复制网站前台页面。
2. 增加独立工作台布局、侧边导航、表格、表单和错误状态。
3. 增加环境变量校验：`CONTENT_REPO_PATH`、目标分支和本地端口。
4. 默认只监听 `127.0.0.1`，不提供公网访问入口。
5. 建立 `/`、`/same-styles`、`/schedule`、`/feed`、`/tags` 页面。

### 产出

- 可启动的独立编辑器空壳。
- “仓库连接检查”页面，显示路径、Git 分支和工作区状态。

### 验收

- 编辑器能启动并读取目标仓库路径。
- 指向不存在或仓库外路径时拒绝启动或写入。

## 4. 本地仓库读取层

### 工作内容

1. 扫描 `content/same-styles/`、`content/schedules/`、`content/feeds/`。
2. 解析 frontmatter 与正文，保留原始文件文本用于安全写回。
3. 为旧文件生成兼容 ID，为新文件读取固定 ID。
4. 在服务端完成搜索、筛选、排序和详情读取。
5. 不读取 `.velite`，避免编辑器显示构建缓存而非本地文件。

### 产出

- `repository reader` 模块。
- 三类内容的统一列表和详情接口。

### 验收

- 编辑器显示的数量、标题、日期、成员和标签与本地文件一致。
- 修改网站文件后重新加载编辑器即可看到变化。

## 5. 写回与 Git 安全层

### 工作内容

1. 只替换表单管理的字段，保留未知 frontmatter 和原始正文。
2. 新内容生成 ULID/UUID 和固定 slug；旧文件不强制改名。
3. 同款图片和 MDX 在同一次本地操作中完成写入。
4. 写入前检查工作区；发现非编辑器的未提交修改时默认停止。
5. 禁止 force push；发生分支冲突时显示冲突文件并停止。
6. 写入后执行 Velite 校验，失败则不 commit/push。
7. 使用可读 commit message，并支持重复点击保护。

### 产出

- 安全的文件写入模块。
- 本地 Git commit、push 和错误反馈模块。

### 验收

- 一次发布最多产生一个内容 commit。
- 图片、MDX 任一环节失败都不会留下不可解释的半成品。
- 用户已有未提交修改不会被覆盖、stash 或 reset。

## 6. 网站侧 Schema 与草稿过滤

### 工作内容

1. 在 `velite.config.ts` 增加兼容的 `id`、`status`、时间模式和时间戳字段。
2. 历史文件缺少 `status` 时默认按 `published`。
3. 在 `src/lib/velite.ts` 暴露统一的已发布集合。
4. 更新首页、同款、行程、动态、搜索、统计和 sitemap 的数据入口。
5. 确认草稿不会进入前台、搜索、统计或 sitemap。

### 产出

- 网站侧兼容 Schema。
- 统一的 `publishedSameStyles`、`publishedSchedules`、`publishedFeeds` 数据出口。

### 验收

- 历史内容的构建结果和前台显示保持不变。
- 新建草稿后，所有公共页面均不可见。
- 发布草稿后，下一次 Vercel 构建可以正常显示。

## 7. 同款完整闭环

### 工作内容

1. 完成列表、搜索、人物/分类/状态筛选和价格排序。
2. 完成新建、编辑、删除确认。
3. 完成图片上传、预览、替换和内容 ID 文件名。
4. 兼容现有 `/static/same-styles/` 图片路径。
5. 保存草稿或立即发布，并显示写入、校验、提交和推送阶段。

### 验收

- 新同款能在本地前台预览，发布后能在网站显示。
- 价格排序、详情弹窗、灯箱切换和旧图片均正常。

## 8. 行程完整闭环

### 工作内容

1. 完成列表、搜索、人物/类型/日期范围/状态筛选。
2. 完成新建、编辑、删除确认。
3. 增加时间模式：具体时间、全天、待定。
4. `description` 作为前台活动说明，兼容历史 `time` 字段。
5. 根据日期计算即将到来、今天和已结束，不保存计算结果。

### 验收

- 三种时间模式在编辑器和网站前台显示正确。
- 修改日期后状态和倒计时自动更新。

## 9. 动态完整闭环

### 工作内容

1. 完成列表、搜索、人物/类型/标签/来源平台/状态筛选。
2. 完成新建、编辑、删除确认。
3. 使用 `description` 作为时间线正文，限制长度并清理不可见字符。
4. 根据 URL hostname 自动识别来源平台，同时允许人工覆盖。
5. 标签候选来自同款和动态的现有标签。

### 验收

- 新动态发布后，时间线能显示标题、日期、成员、类型和正文。
- 短链接、未知域名和非法 URL 不会导致保存流程崩溃。

## 10. 基础标签管理

### 工作内容

1. 合并同款和动态标签，去重并统计使用次数。
2. 表单支持选择已有标签或输入新标签。
3. 提供标签列表和使用位置查看。
4. 暂不提供改名、合并和删除，避免批量重写风险。

### 验收

- 新标签可以被同款和动态使用。
- 标签统计与首页标签云的数据范围一致。

## 11. 联调与回归

### 工作内容

1. 对每类内容执行新建、编辑、草稿、发布、删除全流程。
2. 验证 Git commit、push、Vercel 自动部署链路。
3. 验证 375px、390px、768px 和桌面端编辑器布局。
4. 运行 `npm run lint`、`npx tsc --noEmit`、`npm run build`。
5. 检查草稿、图片、搜索、统计、sitemap 和详情弹窗。

### 验收

- 三类内容全部可独立完成管理闭环。
- 网站前台无草稿泄漏、图片 404、hydration 错误或构建错误。
- 工作区无编辑器之外的意外文件修改。

## 12. 对话交接规则

每完成一个步骤，都更新 [content-editor-progress.md](./content-editor-progress.md)：

```text
当前阶段：
本次完成：
涉及文件：
验证结果：
未完成/阻塞：
关键决定：
下一步：
```

下一次对话的开始顺序：

1. 读取本文件和进度备忘录。
2. 检查网站仓库和独立编辑器仓库的工作区状态。
3. 从备忘录中的“下一步”继续，不重复已验收步骤。
4. 完成后更新备忘录，再决定是否进入下一阶段。
